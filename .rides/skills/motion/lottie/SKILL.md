# Lottie

Play Adobe After Effects (bodymovin) vector animations from `.json` files. Best for: brand illustrations, loading states, empty states, onboarding, icon micro-animations — pre-designed assets, not generated by hand.

## Install

```bash
npm i lottie-react        # React
# or: npm i lottie-web    # vanilla
```

## Usage (React)

```tsx
import Lottie from "lottie-react";
import animation from "./assets/loader.json";

<Lottie animationData={animation} loop autoplay style={{ width: 120, height: 120 }} />
```

Control API: `useLottie` or ref methods — `play()`, `pause()`, `stop()`, `setDirection(-1)`, `goToAndStop(frame, true)`, `setSpeed(2)`.

```tsx
const { View, play, pause, setSpeed } = useLottie({ animationData, loop: false });
```

## Rules

1. Lottie JSON files are code — run them through an analyzer (lottiefiles.com validator) to check for expressions (JS), width/height and frame count; huge files = main-thread jank.
2. Keep per-animation file < 200KB ideally; preload/lazy-load by visibility.
3. Only animate what's visible; pause off-screen (`IntersectionObserver`).
4. Reduce-motion: at `prefers-reduced-motion: reduce`, render the final frame (`goToAndStop(lastFrame)`) or a static SVG/PNG fallback — never run looped animations.
5. Don't ship Lottie for simple icons — use SVG/CSS.
6. Use for empty/loading/success states sparingly (once per screen).
7. In React: `lottie-react` handles cleanup; in vanilla, call `destroy()` on unmount.

## Do / Don't

| Do | Don't |
|---|---|
| Small validated JSONs | 5MB monster animations |
| Pause off-screen | Looping everywhere |
| Static fallback on reduced motion | Lottie for basic UI affordances |
| One hero animation per page | Animation + 3D + particles together |

## Asset sources

- lucide-style icons: no. Brand/illustration animations: lottiefiles.com, icons8, or RIDE asset registry (check license + attribution).
